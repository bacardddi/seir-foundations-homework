Q1: Why did my terminal show root instead of ec2-user when I ran whoami?
    Is it bad to work as root?
AI's answer, in my own words: I most likely switched to root with a command
    like sudo su or sudo -i, which turns the whole session into the admin
    account until I leave it. A prompt ending in # means root and $ means a
    normal user. Working as root is a bad habit because root can delete
    anything with no warning, and files I create as root end up in /root
    and belong to root, which can cause "Permission denied" later. The fix
    is to type exit and only put sudo in front of single commands that
    need it.
How I checked it: I compared my screenshots. All my lab runs end in # with
    [root@...], but my BAM_1.1 screenshot from last week (SSH from my own
    PC) ends in $ and whoami printed ec2-user. I re-read Step 0 of the
    runbook, which expects whoami = ec2-user and pwd = /home/ec2-user.

Q2: What does echo $? do, and why does it show 0, 4, 8 or 12 after the
    COBOL programs?
AI's answer, in my own words: Every Linux program ends by handing back a
    hidden number called an exit code, and $? holds the exit code of the
    last command, so echo $? prints it. It only remembers the very last
    command, so you have to check it right away. 0 means success, and the
    4 / 8 / 12 scale comes from mainframe tradition: higher number, bigger
    problem. 4 = warning (account not found), 8 = the business rules said
    no, 12 = the setup is broken. FastAPI reads this number to decide
    whether to answer "approved", "rejected", or "server error".
How I checked it: I compared my four COBOL screenshots from Run 4.
    account_lookup 100001 gave 0, account_lookup 999999 gave 4 with
    ERROR=ACCOUNT NOT FOUND, both my $0 and 99999999.00 payments gave 8
    with STATUS=REJECTED, and running from the wrong folder gave 12 with
    CANNOT OPEN. Every code matched the AI's table and the homework table.

Q3: When I ran account_lookup from my home folder I got
    ERROR=CANNOT OPEN data/accounts.dat and FILE-STATUS=35. Why did that
    happen?
AI's answer, in my own words: The program opens data/accounts.dat with a
    relative path (no / at the start), so it looks for a data folder inside
    whatever folder I'm currently in. From /opt/balerica-bank the file
    exists, but from my home folder it doesn't. FILE-STATUS=35 is COBOL's
    code for "file not found," and the exit code would be 12. The fix is to
    cd /opt/balerica-bank first, and use pwd if I'm unsure where I am.
How I checked it: My cobol_rc12 screenshot shows that from ~ the command
    failed with CANNOT OPEN, FILE-STATUS=35 and echo $? = 12. Then I ran
    cd /opt/balerica-bank and the same lookup worked in my other
    screenshots with return code 0. Changing only the folder changed the
    result, which proved the folder was the cause.

Q4: What does source venv/bin/activate do, and why do I need it before
    running uvicorn?
AI's answer, in my own words: The installer created a private Python
    environment in /opt/balerica-bank/venv with FastAPI and uvicorn inside.
    Linux finds commands by searching the folders in PATH, and venv/bin is
    normally not on that list, so uvicorn would be "command not found."
    activate puts venv/bin at the front of PATH, and (venv) shows in the
    prompt. It has to be run with source so the change stays in my current
    terminal, and it has to be done again in every new terminal.
How I checked it: In all my lab-run screenshots, (venv) appears at the
    front of the prompt right after source venv/bin/activate, and uvicorn
    starts after that. My Run 5 screenshot shows the installer using
    /opt/balerica-bank/venv/bin/python3 and installing pip into
    /opt/balerica-bank/venv/lib/python3.9/site-packages, which proves the
    packages live inside the venv folder. Step 4 of the runbook also runs
    activate right before uvicorn.

Q5: What does --host 0.0.0.0 --port 8000 mean in the uvicorn command?
AI's answer, in my own words: 0.0.0.0 means the server listens on every
    network address the instance has, and 8000 is the port. That does not
    mean anyone can get in: the security group decides who from outside is
    allowed. Both the server and the security group have to allow it for
    my browser to reach /docs. The AI corrected my wording, because I had
    said 0.0.0.0 means "accept anyone."

Q6: In the Balerica bank, are rejected payments saved to payments.dat?
AI's answer, in my own words: Yes. Both POSTED and REJECTED payments are
    written to the journal. The only time nothing is saved is return code
    12, when the program can't even start (for example, it can't open
    accounts.dat). When I asked if real banks do the same, it said real
    banks also keep rejected payments for audits, fraud checks and customer
    disputes, but usually store them separately from approved payments.
How I checked it: On Run 4 I ran cat data/payments.dat and saw TXN-BW-0001
    and TXN-BW-0002 both marked REJECTED, so rejected payments are saved.
    Then I ran account_lookup 100001 and Alice's balance was still 5000.00,
    so a rejected payment is logged but never moves money. This matched
    the AI's answer.
